# 图片分层 Skill

## 中文触发与首次配置

本 Skill 的中文显示名为“图片分层 Skill”，可由“PSD 分层”“AI 分层”“图片分层”触发。英文内部名为 `image-layering`，不要使用供应商名称作为 Skill 名称。

首次运行且本机没有 APIMart 配置时，主动询问用户 APIMart API URL 和 API Key；URL 可直接回车使用默认值 `https://api.apimart.ai`，API Key 必须使用隐藏输入。将配置写入本机私有 `config/apimart_config.json`（权限 `600`）后再继续运行，绝不把 Key 写入说明、日志或公开仓库。

首次请求 AI 矢量输出且没有 Recraft 配置时，再询问 Recraft API URL，并以隐藏输入询问 Recraft API Key / Token；两者写入本机私有 `config/recraft_config.json`（权限 `600`）。

安装完成后，优先让用户在自己打开的真实终端中运行 `python3 "${CODEX_HOME:-$HOME/.codex}/skills/image-layering/scripts/configure.py"` 完成两套配置。不要在聊天后台代收凭据，也不要把 `split_image.py` 的内部配置函数当作用户配置命令。

## Overview

Use this skill to split one image into a base image plus layer outputs with APIMart Seedream-5.0-Pro. The workflow can be routed into two output branches: PSD-only or PSD + AI vector output. Background and main subject are mandatory PSD assets. The final PSD must always include a full-scene background layer. Do not trust APIMart background output alone; if the returned background is incomplete, synthesize a local full-scene background layer from the base image and the foreground masks before PSD export.

APIMart 的 URL 和 API Key 不内置在 Skill 中；可在首次运行时配置，也可用 `APIMART_API_KEY` 或 `APIMART_BASE_URL` 环境变量覆盖。最大请求档位为 2K。

## Hard quality rules

- Always produce a PSD.
- Enforce a hard 2K ceiling: requested APIMart sizes above 2K and `auto` are normalized to 2K; local source images whose longest edge exceeds 2048 px are compressed to a temporary <=2048 px API input.
- Normalize undersized local inputs before the split request: use pixel dimensions, not file size in KB. If the source long edge is below the requested tier, resize once with Lanczos to the tier long edge (`1K`=1024, `1.5K`=1536, `2K`=2048), preserving aspect ratio. A small compressed file is not automatically low-resolution, so do not upscale based on bytes alone.
- Protect small-source quality during assembly: when a local source's long edge is below the requested tier, enlarge the PSD/AI target canvas once to the tier long edge (`1K`=1024, `1.5K`=1536, `2K`=2048) while preserving aspect ratio. Do not assemble at the original 523x732 (or other sub-tier) canvas and then shrink the completed layers/vector geometry back onto it. For sources already at or above the tier, preserve the original dimensions.
- Produce per-layer SVG, grouped master SVG, and Illustrator-compatible AI output only on the PSD + AI branch.
- Always include a separate background layer when the image has any background.
- Always preserve the base image as 00_base.
- Prefer a native Adobe Illustrator `.ai` with independent semantic layers when Illustrator and `pywin32` are available. If Illustrator is unavailable, use the validated PDF-compatible AI container; this is only an AI-container fallback, never a local vectorization fallback.
- Always try to include the main subject/IP/foreground as an independent layer, and keep each layer as close as possible to the original canvas coordinates and scale.
- Placement is a hard contract: first map each returned PNG to the APIMart metadata `bounding_box` in the target canvas, then map the returned SVG viewBox to the prepared PNG rectangle using its actual SVG viewport width/height. Never reuse a provider upload scale as the final AI placement scale.
- The canonical layer file set is the file list returned by the current task manifest, not a glob of every PNG in the output directory. Before each download, the script removes only stale root-level image files previously generated by this skill; it never touches PSD/vector/report files or unrelated user files. It then removes obsolete downloaded provider-background duplicates and rejects file/metadata count mismatches before PSD/AI assembly.
- When reprocessing with `--task-id`, pass the original image path whenever strict source dimensions or small-source tier upscaling are required. If no original image is available, the script can only use the APIMart base canvas or a full-scene bbox explicitly present in task metadata; it cannot recover an omitted source resolution or safely decide whether a sub-tier canvas should be enlarged.
- Treat target layer counts as best-effort, but never sacrifice the background layer or spatial accuracy to satisfy the count.
- If APIMart returns no background layer, synthesize 01_background-forced.png locally and include it in the PSD.
- Report clearly when the PSD background layer is model-returned versus locally reconstructed. Prefer the local reconstructed background whenever the model background is incomplete.

## Recraft vectorization backend

The PSD assembly stage is unchanged. On the PSD + AI branch, the vector stage **must** use Recraft after the APIMart PNG layers have been downloaded, spatially normalized, and approved by the human PSD quality gate. There is no local vectorization fallback.

```bash
--vector-backend recraft  # mandatory; fail clearly if Recraft is unavailable
--psd-approved            # required only on the second run after human PSD review
```

Recraft uses the image-to-SVG endpoint, not an image-generation endpoint:

```text
POST https://external.api.recraft.ai/v1/images/vectorize
```

首次使用 AI 分层时，Skill 会分别询问 Recraft API URL 和 API Key / Token，并保存到本机私有 `config/recraft_config.json`，不会把凭据发布到仓库。若设置了 `RECRAFT_API_TOKEN` 或 `RECRAFT_VECTORIZE_URL` 环境变量，则环境变量优先：

```powershell
$env:RECRAFT_API_TOKEN = "<token-from-Recraft>"
```

The script uploads each prepared transparent PNG layer separately, with a hard 2048 px maximum edge and 4 MP maximum pixel area, requests the supported `b64_json` response, validates that it contains paths and no embedded `<image>`, and maps the returned SVG back to the original layer coordinate system. The master SVG then performs a second explicit mapping from the returned SVG viewport to the prepared layer rectangle, so a provider response with a different width/height cannot enlarge or shrink an element accidentally. Recraft failures stop the AI branch; they never trigger local tracing.

Use Recraft per-layer mode when the AI must keep independent semantic layers. Whole-image Recraft vectorization is cheaper, but is not the default here because it cannot guarantee independently movable background/IP/text/logo layers. Recraft's API response is still an approximation: pure SVG output cannot promise pixel-identical color/texture reproduction for arbitrary raster input. The Skill therefore must not claim lossless or 100% alignment; it validates and reports the actual path/vector output.

If the Recraft token is unavailable or the Recraft request fails, the AI branch stops with an actionable error. It never silently generates a local vector.

## Output routing

If the user has not explicitly chosen an output branch, ask exactly one question before calling the API:

> 要一份纯 PSD 文件,还是 PSD + AI 两个都要出?

Routing rules:
- PSD only branch: export PSD, skip SVG and AI output (`--no-svg --no-ai`)
- PSD + AI branch: export PSD + SVG + AI-compatible vector files (default vector path)
- If the user already said only PSD or PSD + AI, do not ask again
- If the user requests AI output, keep vector export on even when the PSD is the primary deliverable

## Modes

### 1) 自动拆分
Use this when the user only says to split the image, but does not name the layers and does not give a target layer count.

Examples:
- 把这张图自动拆开
- 极限拆分这张图
- 直接拆层

Behavior:
- Do not pass a prompt
- Do not pass a target layer count
- Let the model infer the main elements
- Preserve exact layer position, size, bbox, and stacking order as much as possible
- Always force a separate background layer
- Still export a PSD

### 2) 引导拆分
Use this when the user names the objects, regions, or semantic parts to extract.

Examples:
- 拆成文字、背景、草、土壤
- 把 IP、logo 和主要元素都拆出来
- 只把某个局部提出来

Behavior:
- Pass a short prompt naming the desired parts
- Use this as the default mode when the user gives clear element names
- Use <bbox> when the user wants a precise local region
- Preserve exact element coordinates and scale as much as possible
- Always force a separate background layer
- Still export a PSD

### 3) 按指定层数拆
Use this when the user gives a layer count, such as 2, 3, 4, or 5 layers.

Examples:
- 拆成 4 层
- 拆成 5 层
- 拆成 3 个图层

Behavior:
- Pass the prompt plus a target layer count
- Treat the count as a best-effort target, not a hard guarantee
- If the image structure allows, prefer matching the requested count
- If the structure does not allow exact matching, return the cleanest useful split
- Preserve exact element coordinates and scale even when matching the requested count
- Never drop the background layer in order to match the target count
- Always force a separate background layer
- Still export a PSD

## Recommended routing

- User says only 只说要拆开这张图 -> 自动拆分
- User says 拆出 A、B、C 这几个 -> 引导拆分
- User says 要拆成 4 个图层 -> 指定层数
- User says both elements and a number -> keep the element names, and treat the number as a target

## Build rules

### APIMart layer split

- Endpoint: POST https://api.apimart.ai/v1/images/generations
- Poll endpoint: GET https://api.apimart.ai/v1/tasks/{task_id}
- Model: read it from `config/apimart_config.json` → `model` (fallback `seedream-5-0-pro`)
  - Also accepted by docs: seedream-5.0-pro
  - Do not hardcode: other providers name the same capability differently
    (e.g. EvoLink `doubao-seedream-5.0-pro-layerize`, kie `seedream/5-pro-layer-decomposition`).
    The canvas 「🔑 分层」panel writes this field — pick from `GET /v1/models` or type any id.
- Input: exactly one PNG or JPEG image
- Layer decomposition output: one base image plus up to 16 PNG layers with alpha
- For decomposition, use size only as 1K, 1.5K, or 2K; `auto` and values above 2K are capped to 2K
- Do not use exact pixel size values for layer decomposition

### Vector/AI export

- The PSD must pass the human quality gate before any Recraft request is made.
- Treat each downloaded PNG layer (or PSD-derived layer PNG) as the source image for an independent Recraft vectorization request.
- Recraft is the only vector backend. Local VTracer, `clean`, `outline`, and any automatic local fallback are disabled.
- Before vectorization, preserve an APIMart-aligned `*_prepared.png` and create a separate `*_trace-input.png`; do not flatten or recolor the layer.
- Recraft uploads are hard-capped at 2048 px maximum edge and 4 MP maximum area. The returned SVG is mapped back to the original validated PSD rectangle.
- Write path-only per-layer SVGs as `01_<layer-name>.svg`. `layers_vector_master.svg` is the sole AI source. `layers_visual_master.svg` is raster-reference-only and must never be used to generate AI.
- Write `vector/layers_vector_master.ai` from the detailed Recraft path-only master SVG and validate the final artifact. If Recraft fails, stop and report the error; do not switch to a local algorithm.
- Keep every layer's canvas geometry, x/y position, width/height, and z-order aligned to the PSD. Use the normalized target canvas from the source/tier policy whenever available; never crop to an arbitrary portrait or square canvas. The same scale must be applied to the base, background, PNG layer bboxes, SVG viewBoxes, and AI placement.
- Exact pixel identity is not mathematically possible when converting arbitrary raster pixels into finite vector paths. Report this limitation honestly, but maximize visual fidelity through Recraft and source-aligned geometry.
- Keep visual-perfect SVG wrappers only for preview/reference and diagnostics; they are not true vectors and are never the AI source.
- Each semantic layer must be a top-level grouped SVG/Illustrator layer so moving the IP layer moves its body, eyes, mouth, outline, and internal details together.

### Canvas normalization and quality gate

- Every run writes `canvas-normalization.json` beside the PSD. It records the requested tier, source canvas, target canvas, scale, and whether a small source was upscaled. Local API-input normalization is recorded in `input-normalization.json`, including the original byte size for diagnostics, but the decision is based on pixel dimensions.
- For example, a `523x732` source at the default `1K` tier becomes a `732x1024` PSD/AI canvas (same aspect ratio, one consistent scale), not a `523x732` final document. This is a local assembly policy; the provider's `1K/1.5K/2K` enum is not itself a mandatory square PSD dimension.
- The PSD layout report and placement report must agree with this target canvas before the AI branch is allowed to run.

### PSD quality gate

When the user requests PSD + AI, use a mandatory two-pass flow:

1. First pass: submit/poll APIMart, download layers, assemble and reopen-validate the PSD, then write `psd-review.json` with status `awaiting_human_review`. Stop before vectorization.
2. Ask the user to inspect the PSD for missing elements, background completeness, canvas ratio, layer order, x/y positions, and layer sizes.
3. Only after an explicit approval, rerun the same task with `--task-id <task_id> --psd-approved --vector-backend recraft`. The script then marks the review approved and sends Recraft requests.
4. If the user does not approve, do not spend Recraft time or tokens.

## Important APIMart response detail

APIMart task polling returns a wrapper like:

```json
{ "code": 200, "data": { "status": "completed", "progress": 100, "result": { ... } } }
```

Scripts must unwrap data and treat both completed and success statuses as success.

## Output structure

The script downloads outputs into:

```text
<output-dir>/<task_id>/
  00_base.png
  01_<layer-name>.png
  02_<layer-name>.png
  layers.psd
  task-result.json
  PSD_README.md
  psd-review.json
  placement-report.json
  psd-layout-report.json
  input-normalization.json       # only when the local input was >2048 px
  vector/                         # only after PSD approval
    01_<layer-name>.svg
    01_<layer-name>_trace-input.png
    01_<layer-name>_visual-perfect.svg
    layers_vector_master.svg
    layers_vector_master.ai
    vector-report.json
    prepared_png/
```

The task-result.json file preserves returned layer names, descriptions, z-index values, sizes, and bounding boxes. The PSD background layer may be a local reconstruction when APIMart background output is incomplete. `placement-report.json` records the canonical file set and target rectangles; `psd-layout-report.json` records the actual reopened PSD layer bounds. `psd-review.json` records whether the human quality gate is awaiting review or approved. Re-running a task is safe against stale root-level PNG mixing because the generated image set is cleaned before download.
